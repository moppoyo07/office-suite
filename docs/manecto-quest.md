# Manecto Quest（業務管理ゲーミフィケーション）仕様書

## 1. コンセプト
Manecto Questは、「やらされ仕事」になりがちな日々のルーチン業務や追客活動を、**ゲーミフィケーション（ポイント制）**によって自発的な行動へと促す機能です。

### 基本思想
*   **「表」は業務サポート:** スタッフ向けの画面では、あくまで「便利なToDoリスト（クエストボード）」として振る舞い、業務の抜け漏れを防ぐことを主目的とします。
*   **「裏」は人事評価データ:** 管理者（社長）向けの画面では、各スタッフの「タスク消化率」「貢献度（獲得ポイント）」を可視化し、ボーナス査定や人事評価の客観的な材料として活用します。

---

## 2. 機能フェーズ

### Phase 1: クエストボード導入（完了）
*   **概要:** トップ画面に「今日のクエスト」を表示し、日次ルーチンタスク（水補給、掃除など）をチェックできる機能。
*   **機能:**
    *   プリセットタスク（固定クエスト）の表示
    *   カスタムタスク（自由入力）の追加
    *   完了時のポイント付与演出（UI上のみ）
    *   Firestoreへの完了履歴保存

### Phase 2: 自動クエスト発行（予定）
*   **概要:** 業務アクションに基づき、システムが自動的に重要なクエストを発行する。
*   **トリガー例:**
    *   「体験利用」終了 → 「お礼連絡（+50pt）」クエスト発行
    *   「最終接触」から7日経過 → 「生存確認連絡（+20pt）」クエスト発行
    *   「ブログ」最終更新から3日経過 → 「ブログ更新（+30pt）」クエスト発行
*   **電光掲示板連携:**
    *   未消化の重要クエスト（追客系）がある場合、ヘッダーの電光掲示板にアラートを流す。

### Phase 3: 社長用評価レポート（予定）
*   **概要:** 管理者が全スタッフのパフォーマンスを確認できる裏ダッシュボード。
*   **機能:**
    *   スタッフ別 月間獲得ポイントランキング
    *   タスク消化率・追客実施数のグラフ化
    *   「サボり検知」（未消化タスクの滞留状況）

## 4. データ構造 (Firestore)

### `staffTasks` コレクション
日々のクエスト消化状況を記録する。

- **Document ID:** `{userId}_{YYYY-MM-DD}_{taskId}`
    - ユニークキーとして日付とタスクIDを含める

- **Fields:**
    - `userId` (string): ユーザID
    - `userName` (string): ユーザ名（非正規化）
    - `date` (string): YYYY-MM-DD
    - `taskId` (string): タスクID（例: `water_refill`, `custom_12345678`）
    - `taskLabel` (string): タスク名
    - `points` (number): 獲得ポイント
    - `status` (string): 'pending' | 'completed'
    - `isPreset` (boolean): プリセットかどうか
    - `completedAt` (timestamp): 完了日時
    - `createdAt` (timestamp): 作成日時
    - `updatedAt` (timestamp): 更新日時
