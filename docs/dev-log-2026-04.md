## 2026-04-13

### LINE返信「ログインが必要です」バグ修正

#### 概要
ダッシュボードからLINEで返信しようとすると「ログインが必要です」エラーが出る問題を修正。

#### 原因
Cloud Functions の `sendLineMessage` が **firebase-functions v1** を使っているのに、`onCall` のシグネチャが **v2形式** `(request)` で書かれていた。v1 の `onCall` は `(data, context)` の2引数で、第1引数にクライアントから送ったデータが入る。そのため `request.auth` は常に `undefined` となり、認証チェックが必ず失敗していた。

#### 修正内容
##### `packages/functions/index.js`
- `onCall(async (request) => {` → `onCall(async (data, context) => {`
- `request.data` → `data`、`request.auth` → `context.auth` に変更

#### 学び
- firebase-functions の v1 と v2 でCallable Function のシグネチャが異なる
  - **v1**: `onCall((data, context) => {})` — `context.auth` で認証
  - **v2**: `onCall((request) => {})` — `request.auth` で認証
- 使用しているSDKバージョンに合わせてシグネチャを確認すること
- ダッシュボード側にはログイン済みでも、Cloud Functions側で `auth` が取れないケースがある

### 活動記録クイック検索（左メニュー検索窓）

#### 概要
左サイドバーの下部に利用者検索窓を設置。名前を打つとリアルタイムで候補が表示され、クリックするとその人の活動記録専用ページに遷移する。活動記録の閲覧・追加をどこからでも素早く行えるようにする。

#### 課題と解決の流れ
1. **最初の実装**: 検索窓を左メニュー上部に配置、候補をドロップダウン表示
   - 問題: IME予測変換がドロップダウンに被って候補が見えない
2. **改善1**: ドロップダウン廃止 → 検索中はメニューリスト自体が検索結果に切り替わる方式に変更
   - 問題: IMEの確定前（ひらがな入力中）に検索結果が更新されない
3. **改善2**: 検索窓をサイドバー下部に移動、結果を上部メニューエリアに表示
   - `InputBase` を uncontrolled（`value` prop なし）にし、`onInput` で IME変換中のひらがなもリアルタイムに取得
   - `nameKana` フィールドとひらがな照合で、変換確定前から候補が出る
   - カタカナ→ひらがな変換関数で `nameKana` がカタカナ登録でもヒット

#### 技術的ポイント
- **IME対応**: React の controlled input (`value` + `onChange`) は IME composition 中に値が確定されない。uncontrolled input (`inputRef` + `onInput`) にすることで、IME変換中のひらがなテキストをリアルタイムに取得できる
- **検索ロジック**: `name`（漢字）と `nameKana`（かな）の両方を照合。カタカナ→ひらがな変換も行い、登録形式に関わらずヒットさせる
- **メニュー切り替え方式**: 検索中は通常のメニューリストが検索結果に置き換わる。ドロップダウン（`position: absolute`）を使わないことでIME候補ウィンドウとの干渉を回避
- **デザイン**: ブルーネオン（`#22d3ee`）で統一、グロウエフェクト付き。`Activity Log` ラベルをネオン文字で表示

#### 変更ファイル

### 重複登録検知 & 再申込み復活機能

#### 概要
新規利用者登録時に同名の既存クライアントを検知して警告表示。ロスト状態のクライアントは「再申込みとして復活」ボタンで新規登録せずにステータスを問合せに戻す。

#### 背景（業務課題）
- 精神的に不安定なクライアントが、ロスト後に再度申し込むケースがある
- スタッフが前回の登録を覚えていないと二重登録になる
- 名前の表記ゆれ（スペースあり/なし）でも別人として登録されてしまう
- 二重登録するとロスト数が増えてCV（コンバージョン率）が悪化する
- しかし新規登録しないと追客リストに載らずスタッフが対応しない

#### 解決策
- **重複検知**: 名前入力時にスペース・全角半角を無視して正規化比較（`normalizeName`）
- **復活機能**: ロスト状態の既存レコードを `inquiry` に戻すことで、1人1レコードを維持
  - ステータスを `inquiry` に変更
  - `contactAttempts`, `nextContactDate`, `lostAtPhase`, `lostReason` をリセット
  - 活動記録に「再申込み（以前ロスト→復活）」を記録
  - 追客リストに自動的に復活する

#### 技術的ポイント
- `normalizeName`: `(name).replace(/[\s\u3000]/g, '').toLowerCase()` でスペース除去＋小文字化
- `useMemo` で入力のたびにフィルタリング（2文字以上で照合開始）
- 復活時は `updateDoc` で既存ドキュメントを更新（新規作成しない）
- 復活と同時に `activity_logs` サブコレクションに記録を追加（経緯が追える）

#### 変更ファイル
##### `src/features/clients/ClientCreatePage.jsx`
- インポート追加: `useEffect`, `useMemo`, `getDocs`, `doc`, `updateDoc`, `query`, `where`, `Alert`, `Chip`, `Stack`, `ReplayIcon`
- `allClients` 取得（`useEffect`）、`duplicates` 算出（`useMemo`）
- `normalizeName` 関数で表記ゆれ吸収
- `handleReactivate` 関数: ステータス復活 + 活動記録追加 + ナビゲーション
- 氏名フィールド直下に重複警告 `Alert` 表示
  - ロスト状態 → 「再申込みとして復活」ボタン（緑）+ 「詳細を見る」ボタン
  - その他ステータス → 「詳細を見る」ボタンのみ

### CV分析: ロスト反映修正 & 累積ファネル方式に改修

#### 概要
ロストが反映されない問題を修正。ファネルを累積方式に変更し、ステータスが進んでも前段階のカウントが減らないようにした。

#### 原因
- ロストのカウントが `createdAt`（問合せ月）ベースだったため、問合せ月以外にロストした人が表示されなかった
- ファネルが現在のステータスのみで判定していたため、見学→体験に進むと見学カウントが減っていた

#### 修正内容
##### `src/pages/CVAnalysisPage.jsx`
- ロストを `closedDate` または `updatedAt` の月で判定するよう変更
- ファネルをマイルストーン日付ベースの累積方式に変更
  - 見学到達: `interviewDate` あり OR 現ステータスが見学以降
  - 体験到達: `trialStartDate` あり OR 現ステータスが体験以降
  - 契約到達: `contractDate` あり OR 現ステータスが契約以降
  - 利用開始: `serviceStartDate` あり OR 現ステータスがアクティブ以降
- `family` ステータスをCV計算から除外
